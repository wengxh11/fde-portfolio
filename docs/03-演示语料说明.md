# 演示语料设计说明

## 设计原则

知识库演示的价值不在"能回答",而在**能回答需要跨文档、跨时间拼起来的问题**。因此 8 份语料刻意做了两条设计:

1. **同一牌号贯穿多份文档**:WC-T8203(导热灌封胶)同时出现在专利、双 85 试验报告、TDS、客户会议纪要中——同一对象的不同生命周期视角,用于演示跨文档溯源;
2. **埋入"失败-整改-通过"剧情**:试验报告 V1 批次失败(500h 保持率 78%)→ 根因(固化剂水分超标)→ 整改(增设入厂水分检验)→ V2 批次通过。这段剧情藏在报告末尾,专门考验检索能否召回"没被直接问到但相关"的关键信息,也是防幻觉提示词第 4 条的验收场景。

## 命名规范

`年份-产品线-牌号-文档类型-版本`,例如 `2025-导热灌封-WC-T8203-双85试验报告-V2`。
命名规范既是检索友好的元信息,也是权限分级(配方/试验=研发可见,客户纪要=销售可见)的管理基础。

## 演示三问(由浅入深)

1. **单文档参数题**:"WC-T8203 的导热系数和固化条件是什么?" → 考基础检索与溯源
2. **跨文档剧情题**:"双 85 测试 1000 小时结果怎么样?之前失败过吗?" → 考召回完整性与"主动补全相关历史"
3. **经验推理题**:"客户产线点胶出现气泡,应该先查什么?" → 考知识库对经验教训的复用价值

> 语料为演示用途的仿真文档,公司名、牌号、数据均为虚构;命名与结构按真实化工企业文档形态设计。
