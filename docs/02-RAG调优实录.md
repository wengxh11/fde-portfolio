# RAG 检索效果调优实录(三个 Badcase 的完整诊断过程)

> 环境:Dify 1.17.1 + SiliconFlow API(对话 Qwen3-14B / 向量 BGE-M3 / 重排 bge-reranker-v2-m3),语料为 8 份化工技术文档。
> 验收标准:参数题答全、失效历史不漏、回答 100% 带引用出处。

## 方法论:查引用 → 验召回 → 改配置

调试 RAG 问答的第一动作永远是**点开回答下方的"引用",看模型实际收到了哪几段文字**——
- 召回里没有正确文档 → 检索层问题(切分/阈值/未开精排);
- 召回正确但答案错误 → 生成层问题(提示词/模型)。

先分清责任层,再动手,不盲调参数。

## Badcase 1:答了导热系数,却说"固化条件未提及"

**现象**:问"WC-T8203 的导热系数和固化条件是什么",回答给出 2.3 W/(m·K),但称固化条件知识库未提及。

**诊断**:点开引用,发现召回的是 TDS 文档被切碎后的零散块——默认按空行(`\n\n`)切块,把"指标表一块、固化特性一块"切开了,模型只收到其中一块。

**根因**:分段切分破坏语义单元——"参数"与"条件"不在同一块。

**修复**:知识库分段设置——分段标识符改为文档内不存在的字符(如 `###`),分段最大长度 1000 → 每份小文档整体成块,重新索引。

**认知沉淀**:切块的目的不是"检索得准"而是"让模型读懂"。块是检索地址,但模型回答时读的是整块内容:切太碎断章取义,切太整定位模糊。小文档整块用,大文档 300~500 字/块加重叠,高要求场景用父子分段(句子检索、段落回答)。

## Badcase 2:模型拒答"知识库中暂无相关信息"(实际召回成功)

**现象**:召回列表里明确有双 85 试验报告,模型却回答"暂无相关信息"。

**诊断**:引用块内容正常 → 生成层问题。此前为防幻觉设的提示词规则"没有答案就明确回答暂无"被模型过度执行。

**修复**:提示词第 3 条改为——"若检索内容与问题无关才回答'暂无';包含部分相关信息必须先作答,不得因信息不完整而拒绝回答"。同时确认召回设置里 Score 阈值开关为**关闭**(rerank 分数普遍偏低,开着 0.7 阈值会大面积误杀召回)。

**认知沉淀**:防幻觉与敢回答是跷跷板,提示词要写"什么时候必须答",不能只写"什么时候不许编"。

## Badcase 3:跨文档的失效历史被漏答

**现象**:问"双 85 测试结果如何?之前失败过吗",通过结果答了,但 V1 批次失败史(埋在报告末尾"结论与建议"段)被漏掉。

**诊断**:该段落未进 Top K——未启用精排,粗筛排序把关键段落挤出了名额。

**修复**:召回设置从"权重设置"(语义 0.7/关键词 0.3 的手工配比)切至 **Rerank 模型** tab,选 bge-reranker-v2-m3,Top K=5;提示词补一条"涉及历史问题、失效、整改的内容,即使没直接问到也要完整提及"。

**认知沉淀**:向量检索是"比坐标距离"的粗筛,快但糙;rerank 把"问题+候选块"逐字对读精排。两段式 = 向量负责快,rerank 负责准。

## 最终验收结果(3/3 通过)

| 验收题 | 通过标准 | 结果 |
|---|---|---|
| 单文档参数题 | 导热系数 2.3 W/(m·K) 与固化条件 80°C×30min+100°C×60min 同时给出,来源 TDS | ✅ |
| 跨文档剧情题 | 1000h 通过 + 主动讲出 V1 批次 500h 失败史(保持率 78%、固化剂水分超标、增设入厂检验) | ✅ |
| 经验推理题 | 第一句即"先查施工环境湿度(≤60%RH)与开封暴露时间(≤24h)" | ✅ |

## 最终配置清单

- 分段:整文档一块(标识符 `###`,长度 1000)
- 检索:混合检索 + Rerank 模型 bge-reranker-v2-m3,Top K=5,Score 阈值关闭
- 提示词(防幻觉四条):

```
1. 回答前完整阅读全部检索内容,逐项核对问题问到的每个要点是否出现,出现了必须给原文数值,不允许只凭一份文档作答;
2. 回答末尾注明来源文档名;
3. 检索内容与问题无关才回答"暂无相关信息";有部分相关信息必须先作答;
4. 涉及历史问题、失效、整改的内容,即使没直接问到也要完整提及。
```
